# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A VitePress-powered personal technical notes site ("BetterWilson Notes") authored in Chinese. Content lives in `docs/<topic>/*.md` (django, drf, python, vue, redis, linux, hadoop, gin, git). There is no application backend — everything is statically generated by VitePress.

## Commands

```bash
npm run docs:dev       # local dev server
npm run docs:build     # build static site into docs/.vitepress/dist
npm run docs:preview   # preview the built site
```

There are no tests, linters, or type checks configured.

## Architecture

### Site config is the single source of truth for navigation
`docs/.vitepress/config.mjs` defines the nav bar **and** every sidebar group. Adding a new markdown page is not enough — you must also register it in the `nav` and the matching `sidebar['/<topic>']` entry, or it will be unreachable from the UI. The `socialLinks`, footer ICP notice, and `ignoreDeadLinks: true` also live here.

### Custom theme extends VitePress DefaultTheme
`docs/.vitepress/theme/index.ts` wires three things on top of the default theme:

1. **Global image zoom** — `medium-zoom` is initialised on every `.main img` in `onMounted`, and a `watch(route.path)` re-runs it after client-side navigation. Without that re-init, zoom breaks when users navigate between pages.
2. **Giscus comments** — `GiscusComment.vue` is rendered via the `doc-after` slot of `Theme.Layout`, so every doc page automatically gets comments. The repo/category IDs are hard-coded to `BetterWilson/blogs-comment-store`.
3. **`<LoginPage />` is registered as a global Vue component** in `enhanceApp`. It is used from `docs/login/index.md` (`layout: page`) and is purely a UI mock — `handleLogin`, `sendCode`, etc. simulate success without any network call. Treat it as a static demo, not a real auth flow.

### Intentional UI restrictions in `theme/global.css`
- `body { user-select: none }` disables text selection site-wide.
- `.copy { display: none !important }` hides VitePress's copy-code button.

These are deliberate (the footer asks readers not to copy content). Don't "fix" them without checking with the author.

### `vite.config.js` is unused
The root `vite.config.js` references `@vitejs/plugin-vue` and an `@ → /src` alias, but there is no `src/` directory and VitePress brings its own Vite pipeline. It is leftover scaffolding — editing it has no effect on the build. Add VitePress overrides via `docs/.vitepress/config.mjs` instead.

### Built output is committed
`docs/.vitepress/dist/` is checked into the repo (current `git status` shows large diffs to dist assets). When changing content or config, rebuild before committing so the deployed snapshot stays in sync — or, if the deploy pipeline rebuilds from source, leave dist alone and avoid accidentally re-committing stale hashed asset filenames.

## Content conventions

- Per-topic image assets live under `docs/<topic>/assets/` and are referenced relatively from the markdown.
- Site-wide static files (logo, favicon, hero illustration) live in `docs/public/` and are referenced as `/logo.png`, `/picture1.svg`, etc.
- The home page (`docs/index.md`) uses VitePress's `layout: home` with hero + features blocks; the login page (`docs/login/index.md`) uses `layout: page` to host the custom Vue component full-bleed.
