# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A VitePress-powered personal technical notes site ("BetterWilson Notes") authored in Chinese. Content lives in `docs/<topic>/*.md` (python, git, django, drf, vue, redis, linux). There is no application backend — everything is statically generated by VitePress. The `docs/login/` page is a UI mock, not a real auth flow.

## Commands

```bash
npm run docs:dev       # local dev server
npm run docs:build     # build static site into docs/.vitepress/dist
npm run docs:preview   # preview the built site
```

There are no tests, linters, or type checks configured.

## Architecture

### Navigation: two sources of truth
- **`docs/.vitepress/config.mjs`** defines the top **nav bar** (`nav`), `socialLinks`, footer/ICP notice, `ignoreDeadLinks: true`, and search config.
- **`docs/.vitepress/sidebar-data.js`** is the single source of truth for **every sidebar group**. `config.mjs` imports `SIDEBAR` from it, and so does `RelatedArticles.vue` (see below). Adding a markdown page is not enough — you must register it here under the matching `/<topic>` key, or it will be unreachable from the UI *and* won't appear in related-articles.

### Custom theme extends VitePress DefaultTheme
`docs/.vitepress/theme/index.ts` extends `DefaultTheme` and wires custom behavior through `setup()` and a custom `Layout()`:

**`Layout()` slot wiring** (this is where custom components attach):
- `layout-top` → `ReadingProgress` (bar).
- `home-hero-image` → `HeroVisual` (replaces the default hero illustration).
- `doc-before` → `ArticleMeta` (category / reading time / char count / last-updated row, article pages only).
- `doc-after` → `RelatedArticles` then `GiscusComment`.

**`setup()` runtime behavior:**
1. **Global image zoom** — `medium-zoom` is initialised on every `.main img` in `onMounted`, and a `watch(route.path)` re-runs it after client-side navigation. Without that re-init, zoom breaks when users navigate between pages.
2. **Scroll-reveal** — `initScrollReveal()` adds a `.reveal` class (opacity:0 → visible) to `.vp-doc` elements via `IntersectionObserver`, and re-runs on route change. The `.reveal` class is added by JS, so content stays visible if JS fails.
3. **`theme-ready` delay** — a 150ms `setTimeout` adds `.theme-ready` to `<html>` so dark-mode color transitions don't fire during initial load (avoids flash). All theme-transition CSS is gated on `html.theme-ready`.

**Custom components** (`docs/.vitepress/theme/components/`):
- `RelatedArticles.vue` — derives "相关文章" from the shared `SIDEBAR`: it locates the current page within its sidebar group, picks prev/next siblings, then backfills from the same group (and sibling groups under the same top-level path). Editing `sidebar-data.js` changes both navigation and related-article recommendations.
- `ArticleMeta.vue` — computes category from the first path segment (with a special-case map: `drf→DRF`, `git→Git`, `vue→Vue`, `go→Go`), and reading time / char count **in the browser** by querying `.vp-doc.textContent` (Chinese reading speed ≈ 400 chars/min). Hidden on home and login pages.
- `GiscusComment.vue` — Giscus comments; repo/category hard-coded to `BetterWilson/blogs-comment-store`.
- `LoginPage.vue` — registered as a global Vue component in `enhanceApp`; used from `docs/login/index.md` (`layout: page`). `handleLogin`, `sendCode`, etc. simulate success with no network call. Treat as a static demo, not a real auth flow.
- `gitalk` is listed in `package.json` dependencies but Giscus is the active comment system — gitalk appears to be leftover.

### Intentional UI / styling in `theme/global.css`
- Nav, sidebar, footer, and content containers are forced **transparent with backdrop-filter blur** so a fixed particle background layer shows through. Several VitePress internal background variables (`--vp-nav-bg-color`, `--vp-sidebar-bg-color`, etc.) are overridden for both light and dark. Don't add opaque backgrounds to these elements or the particle effect breaks.
- The **home page is locked to one screen** on desktop (`@media (min-width:960px) and (min-height:720px)` sets `body:has(.VPHome) .Layout { height:100vh; overflow:hidden }`) and the scrollbar is hidden via `:has(.VPHome)`. Small/short viewports fall back to natural scrolling.
- `--vp-c-gutter` is set to `transparent` globally to remove VitePress's default 1px divider lines between nav/sidebar/footer.
- `prefers-reduced-motion` is respected: hero animations, scroll-reveal, route transitions, and theme transitions are all disabled/reduced under it.

> **Note:** an earlier version of this site disabled text selection site-wide (`user-select: none`) and hid the copy-code button (`.copy { display:none }`). Both rules are now **commented out** in `global.css` — selection and copy are currently enabled. Don't assume the restrictions exist.

### `vite.config.js` is unused
The root `vite.config.js` references `@vitejs/plugin-vue` and an `@ → /src` alias, but there is no `src/` directory and VitePress brings its own Vite pipeline. It is leftover scaffolding — editing it has no effect on the build. Add VitePress overrides via `docs/.vitepress/config.mjs` instead.

### Built output is committed
`docs/.vitepress/dist/` is checked into the repo (commits frequently show large diffs to hashed dist assets). When changing content or config, rebuild before committing so the deployed snapshot stays in sync — or, if the deploy pipeline rebuilds from source, leave dist alone and avoid accidentally re-committing stale hashed asset filenames.

## Content conventions

- Per-topic image assets live under `docs/<topic>/assets/` and are referenced relatively from the markdown.
- Site-wide static files (logo, favicon, hero illustration) live in `docs/public/` and are referenced as `/logo.png`, `/picture1.svg`, etc.
- The home page (`docs/index.md`) uses VitePress's `layout: home` with hero + features blocks; the login page (`docs/login/index.md`) uses `layout: page` to host the custom Vue component full-bleed.
