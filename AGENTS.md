# AGENTS.md

This file provides guidance to Codex and other coding agents when working with code in this repository. It mirrors CLAUDE.md — edit CLAUDE.md and regenerate this file rather than editing it by hand.

## What this is

A VitePress-powered personal technical notes site ("BetterWilson Notes"), bilingual Chinese/English. Content lives in `docs/zh/<topic>/*.md` (default language, `/zh/` prefix) and a mirrored `docs/en/<topic>/*.md` (`/en/` prefix). Topics: python (ConcurrentProgramming / ObjectOriented / supplement), git, django, drf, vue, redis, linux, machine_learning, deep_learning. `docs/index.md` is a `noindex` meta-refresh redirect to `/zh/`. There is no application backend — everything is statically generated by VitePress. The `docs/{zh,en}/login/` pages are a UI mock, not a real auth flow.

## Commands

```bash
npm run docs:dev       # local dev server
npm run docs:build     # build static site into docs/.vitepress/dist
npm run docs:preview   # preview the built site
```

There are no tests, linters, or type checks configured.

## Architecture

### Navigation: two sources of truth
- **`docs/.vitepress/config.mjs`** defines per-locale (`locales.zh` / `locales.en`) **nav bar**, footer/ICP notice, and default-theme UI labels; plus site-wide `socialLinks`, search, sitemap, and SEO head tags.
- **`docs/.vitepress/sidebar-data.js`** is the single source of truth for **every sidebar group**, exporting `SIDEBAR` (zh) and `SIDEBAR_EN` (en). `config.mjs` imports both, and so does `RelatedArticles.vue` (see below). Adding a markdown page is not enough — you must register it here under the matching `/zh/<topic>` and `/en/<topic>` keys, or it will be unreachable from the UI *and* won't appear in related-articles.

### Site config behaviors worth knowing (`config.mjs`)
- **`lastUpdated: true`** (site level) is required for `page.lastUpdated` to exist. `ArticleMeta.vue`'s date and the locale `lastUpdated.text` labels both depend on it — the per-locale `themeConfig.lastUpdated` only sets the label text.
- **`ignoreDeadLinks`** is an allow-list, not `true`. Keep it that way: a blanket `true` previously hid image paths that failed to render.
- **Canonical / hreflang** — `transformHead` emits `canonical`, `og:*`, and zh/en `hreflang` alternates. `ogPath()` appends `.html` because `cleanUrls` is off; canonical must match the real link URLs. If you ever enable `cleanUrls`, drop the `.html` suffix there too.
- **Sitemap** — `sitemap.transformItems` drops the `noindex` pages (root redirect, login). Keep those two lists in sync.
- **Chinese search** — `tokenizeCJK` is passed as `search.options.miniSearch.options.tokenize`. VitePress serializes it into the client bundle, so it runs at both index time (Node) and query time (browser). **The function body must be self-contained** — it cannot reference any module-scope variable or import.
- **UI labels** — default-theme strings (`docFooter`, `returnToTopLabel`, `sidebarMenuLabel`, search box `translations`, `notFound`, …) do **not** follow `lang`. They are overridden explicitly under `locales.zh`; any new default-theme UI needs the same.

### Custom theme extends VitePress DefaultTheme
`docs/.vitepress/theme/index.ts` extends `DefaultTheme` and wires custom behavior through `setup()` and a custom `Layout()`:

**`Layout()` slot wiring** (this is where custom components attach):
- `layout-top` → `ReadingProgress` (bar).
- `home-hero-image` → `HeroVisual` (replaces the default hero illustration).
- `doc-before` → `ArticleMeta` (category / reading time / char count / last-updated row, article pages only).
- `doc-after` → `RelatedArticles` then `GiscusComment`.

**`setup()` runtime behavior:**
1. **Global image zoom** — `medium-zoom` is initialised on every `.main img` in `onMounted`, and a `watch(route.path)` re-runs it after client-side navigation. Without that re-init, zoom breaks when users navigate between pages.
2. **Scroll-reveal** — `initScrollReveal()` adds a `.reveal` class (opacity:0 → visible) to `.vp-doc` elements via `IntersectionObserver`, and re-runs on route change. The `.reveal` class is added by JS, so content stays visible if JS fails.
3. **`theme-ready` delay** — a 150ms `setTimeout` adds `.theme-ready` to `<html>` so dark-mode color transitions don't fire during initial load (avoids flash). All theme-transition CSS is gated on `html.theme-ready`.

**Custom components** (`docs/.vitepress/theme/components/`):
- `RelatedArticles.vue` — derives "相关文章" from the shared `SIDEBAR`: it locates the current page within its sidebar group, picks prev/next siblings, then backfills from the same group (and sibling groups under the same top-level path). Editing `sidebar-data.js` changes both navigation and related-article recommendations.
- `ArticleMeta.vue` — computes category from the first path segment (with a special-case map: `drf→DRF`, `git→Git`, `vue→Vue`, `go→Go`), and reading time / char count **in the browser** by querying `.vp-doc.textContent` (Chinese reading speed ≈ 400 chars/min). Hidden on home and login pages.
- `GiscusComment.vue` — Giscus comments; repo/category hard-coded to `BetterWilson/blogs-comment-store`.
- `LoginPage.vue` — registered as a global Vue component in `enhanceApp`; used from `docs/{zh,en}/login/index.md` (`layout: page`). `handleLogin`, `sendCode`, etc. simulate success with no network call. Treat as a static demo, not a real auth flow. Those pages carry `noindex` + `search: false`.
- Giscus is the only comment system.

### Intentional UI / styling in `theme/global.css`
- Nav, sidebar, footer, and content containers are forced **transparent with backdrop-filter blur**. Several VitePress internal background variables (`--vp-nav-bg-color`, `--vp-sidebar-bg-color`, etc.) are overridden for both light and dark. (Older notes mention a fixed particle background behind them — no such layer exists in the current code; the blur now just shows the page background.)
- The **home page is locked to one screen** on desktop (`@media (min-width:960px) and (min-height:720px)` sets `body:has(.VPHome) .Layout { height:100vh; overflow:hidden }`) and the scrollbar is hidden via `:has(.VPHome)`. Small/short viewports fall back to natural scrolling.
- `--vp-c-gutter` is set to `transparent` globally to remove VitePress's default 1px divider lines between nav/sidebar/footer.
- `prefers-reduced-motion` is respected: hero animations, scroll-reveal, route transitions, and theme transitions are all disabled/reduced under it.

> **Note:** an earlier version of this site disabled text selection site-wide (`user-select: none`) and hid the copy-code button (`.copy { display:none }`). Both rules are now **commented out** in `global.css` — selection and copy are currently enabled. Don't assume the restrictions exist.

### Vite overrides
There is no root `vite.config.js` (an unused leftover was removed). VitePress brings its own Vite pipeline — add Vite options under `vite:` in `docs/.vitepress/config.mjs`.

### Built output is committed
`docs/.vitepress/dist/` is intentionally checked in — the live site is published straight from it. When changing content or config, run `npm run docs:build` before committing so the deployed snapshot stays in sync. `.gitattributes` marks dist as `-diff linguist-generated`. `docs/.vitepress/cache/` is local-only and gitignored.

## Content conventions

- **Images live in `docs/public/images/<topic>/`** and are referenced by absolute path, e.g. `![alt](/images/redis/foo.png)`. zh and en pages share one copy — never add per-locale `assets/` folders (they were previously duplicated byte-for-byte, ~108 MB). Use kebab-case ASCII filenames with no spaces: a space in a markdown image path makes markdown-it render the whole `![...](...)` as literal text.
- Every page should have a `description:` in frontmatter (used for `<meta description>` and `og:description`), and exactly one `#` H1.
- Site-wide static files (logo, favicons) also live in `docs/public/` and are referenced as `/logo.png`, etc.
- The home pages (`docs/{zh,en}/index.md`) use VitePress's `layout: home` with hero + features blocks; the login pages use `layout: page` to host the custom Vue component full-bleed.
- Line endings are normalized to LF via `.gitattributes`.
